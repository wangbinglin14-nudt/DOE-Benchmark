## Collection process

- **How generated.** Each case implements a documented low-order physical model (for example Euler--Bernoulli beam eigenvalue problems, lumped thermal networks, Breguet-range surrogates) behind a common normalised `BaseCase.evaluate` interface.
- **Sampling.** Inputs are sampled by the benchmark samplers; ground truth comes from the simulator itself, so no measurement noise enters the case library.
- **Validation.** Cases carry targeted physics regression tests that pin equations, trends and failure contracts. Evidence tiers separate cases with external validation notes from plausibility-only cases; see `docs/CASE_VALIDATION_SUMMARY.md` and `docs/case_validation_status.csv`.

## Uses

- **Intended use.** Benchmarking sampling, surrogate-model and reliability-estimation methods; studying analytical-to-physical transfer of method rankings, sample budgets and risk calibration.
- **Out-of-scope use.** The cases are low-order simulators, not validated high-fidelity models. They must not be used as certified safety, certification or design-approval evidence, and quantitative estimates apply only to the tested case panel, domains and budgets.
- **Known limitations.** Deterministic and single-fidelity; plausibility-only cases lack external case-level validation; the case identifiers' `_Nd` suffixes sometimes denote physical spatial dimension rather than input dimension.
